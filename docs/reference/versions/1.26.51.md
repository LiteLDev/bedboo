# Bedrock 1.26.51

Notes for the 1.26.51 protocol family, the default version: **protocol 2193**, BDS **1.26.50.5**, **1.26.51.1**
and **1.26.52.3**. Pass `version: '1.26.51'` or any of these builds to `createBot` (or nothing: `false` and an absent
`version` mean 1.26.51); `bot.version` is then `'1.26.51'` and `bot.protocolVersion` 2193. The rest of this reference
describes this family unless a page says otherwise (see [BDS notes](../bds.md) and
[Connection and versions](../differences/connection.md#versions)).

## Data {#data}

`@bedboo/bedrock-data` ships `data/1.26.51/`, generated by `scripts/generate.js --version 1.26.51` from the sources
pinned in `scripts/sources.js` `PINS['1.26.51']` and the live probe `scripts/probe/1.26.51.json` (BDS 1.26.51.1):
22 091 block states, 2 076 items, 89 vanilla biomes. The package's `NOTICE.md` lists the sources.

## One data set for three builds {#builds}

The three BDS builds share the protocol and the game data. Each build was started natively and joined as
`version: '1.26.51'`, and the static join data was compared with BDS 1.26.51.1, the build the data comes from:

| Compared | 1.26.50.5 | 1.26.52.3 |
|---|---|---|
| `start_game`: block palette checksum, `block_network_ids_are_hashes`, the 98 `block_properties`, experiments, game rules | same | same |
| `item_registry`: 2 076 items, each with the same runtime id, `component_based` and version | same | same |
| `creative_content`: 124 groups, 1 980 entries | same | same |
| `biome_definition_list`: 89 definitions | same | same |
| `crafting_data`: every recipe and its network id (the per-run recipe UUIDs aside) | same | same |
| `available_entity_identifiers`, `voxel_shapes`, `trim_data`, `camera_presets`, `unlocked_recipes`, … | same | same |
| `available_commands`: the 82 commands, their overloads, parameter type ids and enum contents | same | same |
| probe: effect ids, enchantment ids, biome order, entity bounding boxes | same | same |

The only differences are server-side or cosmetic:

- `start_game.engine` is the build (`1.26.50`, `1.26.52`).
- `available_commands` lists the world-generation feature names of `/place feature` in another order (same names);
  bedboo resolves enum values through each packet's own value table, so nothing depends on the order.
- BDS 1.26.50.5 sends other `jigsaw_structure_data` template pools (structure generation, unused by bedboo).

So `data/1.26.51/`, the feature table and the command type ids serve all three builds; no build-specific table
exists. bedboo was also run against each build (spawn, registry, `blockAt`, inventory, chat, physics walk, dig, place,
entity tracking, tab completion, disconnect) with no difference.

## Tests {#tests}

`pnpm test` runs the unit tests against this family (`BEDBOO_VERSION=1.26.51`, or a build such as
`BEDBOO_VERSION=1.26.52.3`, selects it explicitly). Its join capture is `test/fixtures/1.26.51/join_flat` (BDS
1.26.51.1).
