# Parity tracking

Goal: every mineflayer 4.39.0 export, bot property, method, event, window-class member and external test
is either implemented and asserted by a test, or a documented inherent Java/Bedrock difference.

## Fragment scheme

- `U0-seed.md` — the complete checklist (generated by U0 from `docs/upstream/`): every item with its owner
  unit, all `todo`.
- `<unit>.md` (e.g. `U8.md`) — each unit's fragment. Copy your rows from the seed (and add rows for anything
  the seed missed), using the columns from `_template.md`. Only the owning unit edits its fragment, so units of
  the same wave never conflict.
- At each wave gate the coordinator runs U3's tooling (`scripts/parity/`) to assemble the seed + fragments into
  `docs/parity.md` (a fragment row overrides the seed row with the same `item` + `kind`). Rows still `todo` or
  without an asserting test are reported.

## Columns

| column | meaning |
|---|---|
| item | exact member as in the seed, e.g. `` `bot.equip` ``, `` `entityHurt` ``, `` `Furnace .takeFuel()` ``, `` `useChests` `` |
| kind | `property` / `method` / `event` / `test` / `export` |
| owner | unit id (`U8`), multi-wave as `U4 → U5` |
| status | `todo`, `done` (identical behaviour), `adapted` (works, with a documented Bedrock adaptation), `n.a.` (inherent difference, cannot exist on Bedrock) |
| asserting test | `path/to/file.test.js` › test name that proves the row (required for `done`/`adapted`); for `n.a.` link the differences entry |

`adapted` and `n.a.` rows must link an entry in `docs/differences/<unit>.md`.
