# Parity — U3 (parity tooling)

U3 delivers the tooling that keeps this matrix honest rather than API members:

- **Conformance test** — `packages/mineflayer-bedrock/test/unit/conformance/` (runs with `corepack pnpm test`).
  It builds the mineflayer 4.39.0 reference surface from upstream itself: a real mineflayer bot on a fake Java
  client (plugins injected, then a `login` replayed), its window openers, a static scan of mineflayer's `lib/`,
  `docs/upstream/index.d.ts` read with the TypeScript compiler, and master's `abilities.js`. It compares that surface
  with mineflayer-bedrock: a fake bedrock-protocol client, the same window probe, and a replay of the recorded BDS
  join (`test/fixtures` `join_flat`). It also checks `index.d.ts` against upstream's.
  Missing members, wrong arity, wrong sync/promise kind or value type, extra top-level members, export or d.ts gaps,
  events without a parity row and parity errors **fail now**. `notImplemented` stubs, members not yet produced by the
  join replay, window members behind stubbed openers and events without an asserting test are **pending**, and fail
  only in strict mode: `BEDBOO_CONFORMANCE_STRICT=1`, or `STRICT = true` in `conformance/config.js`, which the
  coordinator flips for the final waves. `BEDBOO_CONFORMANCE_REPORT=1` lists every pending item.
- **Parity assembly** — `corepack pnpm parity` (`scripts/parity/`) merges `docs/parity/*.md` into
  [`docs/parity.md`](../parity.md) and `docs/differences/*.md` into [`docs/differences.md`](../differences.md), with
  coverage per unit and per kind. `--check` exits 1 on errors: no owner, bad kind or status, a row the unit does not
  own, a duplicate claim, done/adapted without an existing asserting test, adapted/n.a. without a valid differences
  link, or an upstream item that no fragment lists. `--final` also rejects `todo` rows.
- **internalTest mapping** — [`U3-internal-tests.md`](U3-internal-tests.md) maps every `describe`/`it` of mineflayer's
  `test/internalTest.js` to its owner and planned Bedrock test.

Fragment rules enforced by the tooling (they extend `README.md`):

- An item is identified by its kind plus its canonical name. The code span in the item cell is the name; text after
  it is a note; call arguments of methods are ignored. For example, `` `Furnace .putFuel(itemType, metadata, count)` ``
  is the same item as `` `Furnace .putFuel()` ``.
- A unit's fragment may only list items whose checklist row (seed or `<!-- parity:seed -->` file) names that unit in
  its owner column. When both units of a hand-off (`U4 → U5`) list an item, the later unit's row wins.
- An asserting test that names a `*.test.js` path must point to a file that exists.
