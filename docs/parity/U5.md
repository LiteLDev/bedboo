# Parity — U5 (physics & movement)

U5 replaces U4's stationary physics stub with an in-repo Bedrock engine (`lib/physics/`, a prismarine-physics 1.11.1
fork calibrated against BDS 1.26.51.1) and the real `player_auth_input` provider: one engine step per server tick,
every input flag, rewind + replay on `correct_player_move_prediction`, BDS teleport / knockback / effect timing,
creative flight (`request_ability`) with a physics-driven `flyTo`, elytra gliding and vehicle input.

Asserting tests:
- unit (no server): `test/unit/physics.test.js` (engine), `test/unit/physics_plugin.test.js` (plugin on the recorded
  join, internalTest analogs), `test/unit/physics_contract.test.js` (mineflayer-pathfinder `lib/physics.js` on the
  engine), `test/unit/physics_traces.test.js` (offline replay of the BDS traces in `test/fixtures/physics/`),
  `test/unit/physics_stub.test.js` (U4's surface contract, kept);
- e2e (BDS): `test/external/physicsLoop.test.js` (60 s acceptance loops, default and 0.1 threshold),
  `test/external/physicsBlocks.test.js`, `test/external/physicsFlight.test.js`, and U7's
  `test/external/vehicles.test.js` › "moveVehicle steers the boat (physics plugin, U5)".

`bot.moveVehicle` is implemented here (physics.js replaces the stub that entities.js defines; the row stays in U7's
fragment, flipped to `adapted` with the vehicles test above, which no longer skips). `bot.creative.flyTo` (U8) delegates to
`bot._bedrock.physics.flyTo`. `adapted` rows link [docs/differences/U5.md](../differences/U5.md).
